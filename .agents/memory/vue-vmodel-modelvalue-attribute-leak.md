# Vue wrapper `v-model` leaks a `modelvalue` attribute onto the custom element host

With `v-model` on any `componentModels` component, the rendered host carries `modelvalue="<value>"` in addition to the correct `value` property. Cosmetic (the element ignores it) but invalid markup, and it reveals that the wrapper's own model container prop is being forwarded to the element.

**Root cause (upstream, still present in `@stencil/vue-output-target@0.14.6` and on `main`):** in the installed `dist/runtime.js`'s `defineContainer`, the container declares the model prop with `props[MODEL_VALUE] = DEFAULT_EMPTY_PROP` (0.13.1 line 168) and then copies **every** declared prop onto the rendered element in `for (const key in props) { … propsToAdd[key] = value … }` (lines 275–278). `modelValue` is one of those props, so it reaches the element as a vnode prop. Vue's `patchProp` → `shouldSetAsProp` ends with `return key in el` (`@vue/runtime-dom@3.5.30` line 833); a custom element has no `modelValue` property, so the write falls through to `patchAttr` → `setAttribute('modelValue', …)`, which HTML lowercases to `modelvalue`. Proven by spying on `Element.prototype.setAttribute` and reading the stack: `mountElement → patchProp → patchAttr`.

**No config option exists.** `ComponentModelConfig` is only `{ elements, event, targetAttr, eventAttr? }`; the container prop name `modelValue` is hard-coded in the runtime and there is no prop allow-list or runtime option. Upstreaming the one-line fix (`skip MODEL_VALUE` in that loop) is the only real alternative.

**Fix shape used in this repo (EOA-19597 T27):** the generated proxies must import a runtime we own. `packages/boreal-web-components/targets/vue-output-target.ts` wraps the output target's `generator`, and after generation rewrites the single specifier `'@stencil/vue-output-target/runtime'` → `'./runtime.js'` (throwing if the specifier is absent, so a silent no-op is impossible). `packages/boreal-vue/lib/runtime.ts` re-exports that runtime and overrides `defineContainer` with one that wraps the container in a guard component when `modelProp` is set: the guard declares `modelValue`, forwards it to the real model prop (`value`/`checked`/`files`/`selectedRows`), forwards `attrs` + slots, and re-emits `update:modelValue`. Non-model containers are returned untouched.

**Constraints worth remembering:** the generated proxies' relative import must keep its `.js` extension (tsc emits specifiers verbatim and `dist/components.js` is consumed as Node ESM); `targets/` is outside both `tsconfig.json`'s `include` and the package ESLint config, so `targets/*.ts` is transpiled without type-checking — type-check it explicitly; and `packages/boreal-vue/lib/components.ts` is not a Turborepo `outputs` entry, so a cached `boreal-web-components#build` skips regeneration (pre-existing).
