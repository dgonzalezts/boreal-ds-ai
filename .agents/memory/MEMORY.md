**Boolean prop naming** — `@Prop()` booleans must not carry an `is`, `has`, or `show` prefix. Use single descriptive adjectives that match native HTML attribute style (`disabled`, `closable`, `required`, `counter`). Examples: `hasClear` → `clearable`; `showClose` → `closable`; `hasHeader` → `header`.

**Custom event naming** — `@Event()` names follow `bds{Action}` camelCase. No component noun in the middle (`bdsClose`, not `bdsBannerClose`). Exception: `valueChange` is reserved for Vue `v-model` integration. Full failure modes for native event names: `ai-docs/guidelines/stencil-best-practices.md` § "Custom event naming".

### Bash Tool — `kill`/`pkill` Hazards in a Shared Session

Two distinct, verified failure modes when signaling processes from the Bash tool. Not the same lesson — one is the sandbox silently blocking a kill against the intended target, the other is a successful kill collaterally killing an unintended survivor.

| File                                                   | What it covers                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kill-sandbox-boundary-for-background-tasks.md`        | Plain `kill`/`kill -9` from a normal (sandboxed) Bash call silently fails against processes spawned by *earlier* Bash tool calls — no useful stderr, target stays alive. Use `TaskStop` for harness-tracked background tasks; fall back to `kill -9` with `dangerouslyDisableSandbox: true` only for genuine orphans, after tracing the full process tree. Also covers zsh `$VAR` word-splitting. |
| `plain-kill-can-take-down-unrelated-background-job.md` | A `kill <pid>` targeting stale, unrelated processes from an earlier session can collaterally kill your OWN currently-running, unrelated background job (`&`/`disown`-started) in the same session, even with no parent/child relationship between the PIDs. Prefer `run_in_background: true` over manual `&`/`disown`; re-verify survivors with `curl`/`ps` after every subsequent `kill` call.  |

### Stencil — Non-Shadow Slot Lifecycle Timing

| File                                                | What it covers                                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stencil-non-shadow-slot-relocation-timing.md`      | Non-shadow (light DOM) Stencil components relocate default-slot children out of the host's direct `childNodes` during the first render, which completes before `componentDidLoad`. Any direct-childNodes slot-content check (e.g. `hasSlotContent(this.el)`) must run in `componentWillLoad` instead. Named-slot `querySelector` lookups are unaffected. Real bug found in `bds-button`'s `checkAccessibleName()`. Also: `hasSlotContent`'s original `node.slot === ''` check silently always returns `false` in Stencil's `mock-doc` test environment (no `.slot` property reflection there) — use `!node.hasAttribute('slot')` instead. |
| `stencil-dev-server-stale-lazy-chunk.md`            | `pnpm dev:components` (no Storybook layer) can, after a long-running `--watch` session with many rebuilds, serve a stale content-hashed lazy chunk (`p-[hash].entry.js`) independently of a correctly-updating friendly-named artifact (`<component>.entry.js`) — survives plain server restarts. | `stencil-conditional-slot-target-orphans-parent-content.md` | Toggling a light-DOM child's boolean prop that gates a named `<slot>` (e.g. `bds-popover`'s `header`/`footer`) does NOT hide the parent's own `slot="..."` JSX for that name — the parent must independently gate every piece of its own slotted content with the same condition, or it paints orphaned/unrelocated. `newSpecPage` never catches this (asserts JS properties, not paint); found live in a real browser. Real bug in `bds-date-picker`'s `calendarType='default'` (Task 15c, EOA-17138). |

### Cross-Browser — Safari-Specific Rendering & Interaction Bugs

> `apps/boreal-docs/src/stories/welcome.mdx` § "Browser Support" is the documented, versioned browser-support commitment this library makes to consumers. Every file below was found verifying/fixing behavior against that commitment — treat this section as the standing list of known Safari risk categories to check against for any new interactive, animated, virtualized, or drag-and-drop feature, not just a historical log.

| File                                                                       | What it covers                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `bds-button-group-role-group-vs-toolbar-ancestor-conflation.md`            | `bds-button-group`'s `_setupKeyboard()` conflated an explicit `role="group"` prop with being nested inside a `[role="toolbar"]` ancestor under the same resolved `_role` value, silently skipping roving-tabindex setup for both. Broke Tab/Arrow navigation for `bds-table`'s toolbar buttons; most visible in Safari's stricter ARIA-group Tab-order handling, but the bug itself was a plain logic conflation, not Safari-specific. |
| `safari-focus-ring-transform-child-ghosting.md`                            | Safari's native `outline` focus ring combined with a CSS-`transform`-animated child (e.g. a rotating chevron) can render a ghosted/duplicated artifact, not reproducible in Chrome/Firefox. Fix: always pair `outline: none` with a custom `:focus-visible` box-shadow ring on the same element — the established convention in `bds-button`/`bds-checkbox`/`bds-button-group`, missing on two `bds-table` elements.                |
| `safari-virtualized-row-transition-on-remount.md`                          | Rows scrolled outside a virtualizer's overscan window are fully unmounted and remounted as brand-new DOM nodes, even with correct identity-based VDOM keying. Safari can spuriously animate a freshly-inserted element's attribute-driven CSS transform on first paint; `will-change: transform` alone does not reliably prevent it. Fix: `transition: none` (and `will-change: auto`) scoped to virtualized rows.                 |
| `native-drag-drop-child-element-event-churn.md`                            | Native drag events follow pointer-event hit-testing — nested interactive children inside a drag source/target cause `dragenter`/`dragleave` churn as the pointer crosses them mid-drag, visible as cursor flicker on Windows. Fix: `pointer-events: none` on all descendants while dragging (toggled on the `dragstart`/`dragend` pair, never `mousedown`), plus a `relatedTarget`-containment guard in `dragleave`.                |
| `keyboard-triggered-focus-move-double-activation.md`                       | A keyboard-activated (Space/Enter) handler that opens a related UI and synchronously moves focus into it can cause the triggering key event to double-activate the newly-focused item. Fix: defer the focus move via `requestAnimationFrame()`. Reproduces on all browsers, not Safari-specific.                                                                                                                                   |
| `stencil-getcomputedstyle-custom-property-unmockable.md`                   | A component's bare `getComputedStyle(this.el)` call cannot be intercepted from a Jest spec under `newSpecPage` — Stencil's Jest setup pre-binds a separate `global.getComputedStyle` reference before any test runs, and mock-doc's own implementation always returns `''` regardless of the element.
