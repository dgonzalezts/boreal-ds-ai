Confirmed empirically (probe script run via `stencil test --spec`) that Stencil's Jest test environment (`@stencil/core/testing`'s bundled `jest-environment.js`, Puppeteer-based) provides **no native `MutationObserver` or `ResizeObserver` global at all** — `typeof MutationObserver` is `undefined` in a plain spec file with no mocks installed. `document`/`window` are mock-doc instances, not jsdom, and mock-doc itself never implements `MutationObserver`/`ResizeObserver` either.

This means `setupMutationObserverMock()` / `setupResizeObserverMock()` (`packages/boreal-web-components/src/utils/testing/mocks/observers.ts`) are not "polyfills that let a real observer run in a test-friendly way" — they install a permanent no-op stub (`observe`/`disconnect` are `jest.fn()`, never fires any callback) purely so component code that calls `new MutationObserver(...)` doesn't crash with a `ReferenceError`. Any test that needs the *retry/callback* behavior of a `MutationObserver` (e.g. a late-population race handled by re-observing and calling `forceUpdate`) will silently never see the callback fire if it relies on the shared mock — the test will fail in a way that looks like the component is broken, when actually the mock just never invokes anything.

**Fix:** build a small functional test double scoped to just the tests that need it (a nested `describe` with its own `beforeEach`/`afterEach` swapping `global.MutationObserver`, restoring the previous value — usually the shared no-op mock — afterward so sibling tests in the same file are unaffected). The double should record each `observe(target)` call so the test can manually invoke that specific instance's callback after performing the real DOM mutation the code depends on (e.g. `template.content.appendChild(...)`) — this exercises the actual wiring (observer created → correct target → callback disconnects/removes itself/calls `forceUpdate`) without needing real async mutation-record delivery, which doesn't exist in this environment anyway.

**Watch for multiple concurrent `new MutationObserver(...)` call sites sharing the same global constructor.** `bds-table` also creates a `_columnObserver` in `componentDidLoad` (observing `this.el` for `bds-table-column` child changes) that is unrelated to a feature-specific observer (e.g. `watchForLateTemplateContent`'s per-column late-content retry, observing `template.content`). A naive test double that records *every* `new MutationObserver()` call will catch both, breaking a `toHaveLength(1)` assertion. Filter recorded instances by target identity (`instance.target === expectedNode`), not by call order or count, to isolate only the observer(s) relevant to the feature under test. Verified while adding a regression test for `bds-table`'s `<template slot="cell">` late-population retry (EOA-16000 Task 3 follow-up).

Candidate for promotion to `.agents/memory/` — this is a cross-cutting Stencil test-environment fact, not specific to this subagent.
