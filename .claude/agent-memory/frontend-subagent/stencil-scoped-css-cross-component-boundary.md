Stencil's non-shadow "scoped" CSS (used by all light-DOM `shadow:false` components in this codebase per [[feedback_no_shadow_false]]) transforms every selector at build time to append the authoring component's own scoping attribute/class to each compound part of the selector. A rule like `bds-date-picker [some-attr] { ... }` declared in `bds-date-picker.scss` compiles to something requiring `bds-date-picker`'s scoping marker on BOTH the ancestor and the descendant — so it silently fails to match a descendant rendered by a *different* component (e.g. `.bds-text-field__container` inside a slotted `<bds-text-field>`), even though the plain-CSS selector would obviously match in the DOM. No build error, no warning — the rule just never applies.

**Why:** discovered fixing EOA-17138 Task 19o (`bds-date-picker` transient invalid-flash on day-click commit). The fix needed to suppress `bds-text-field`'s own transition for a brief window after `bds-date-picker` clears an error it had set. A rule in `bds-date-picker.scss` targeting a `data-` attribute set on the field's own container looked correct, compiled without error, and simply never took effect — cost significant debugging time before realizing the selector was being scoped away from its target.

**How to apply:** any time a fix needs a CSS rule to reach into a *different* component's own rendered markup (not just an immediate host-owned or `::slotted`-style boundary), a scoped `.scss` rule cannot do it. Options: (1) put the rule in the *other* component's own `.scss` file if in scope to touch it, or (2) inject a plain unscoped `<style>` tag into `document.head` imperatively from JS (bypasses Stencil's scoping entirely since it's not part of any component's compiled styles) — this is the pattern used for the Task 19o fix (`ensureSkipFieldTransitionStyle` in `bds-date-picker.tsx`). Also note: an *inline* `element.style.foo = ...` override on a node belonging to another component does not survive that component's own re-renders — Stencil's vdom patch clears inline `style` attributes it doesn't itself manage on every re-render, even ones set imperatively from outside. A `data-` attribute is NOT touched by that patch, so pairing it with an injected global stylesheet rule (not inline style) is the durable combination.
