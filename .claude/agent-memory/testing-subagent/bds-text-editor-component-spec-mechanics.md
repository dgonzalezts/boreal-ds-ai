Component specs share `__test__/bds-text-editor.test-utils.ts` (not a spec; precedent `search-bar-items.test-utils.ts`). Mount with `page.doc.createElement('bds-text-editor')` + `Object.assign(el, props)` before `appendChild`, so object props (`fields`, `labels`, `customValidators`) exist at first render; `page.rootInstance` is the editor when it is the first registered tag. Register `BdsTextEditor, BdsPopover, BdsTextField, BdsTypography` only: without `BdsPopover`, `componentDidRender` throws `popover.setAnchorElement is not a function`. Unregistered children (`bds-toolbar`, `bds-button`, `bds-dropdown`, `bds-list-menu-item`, `bds-divider`) get primitive props as attributes (`getAttribute('border')`, `hasAttribute('disabled')`); the registered popover and text field expose properties (`floatingOptions`, `error`, `errorMessage`).

- The view is reachable only through the private `adapter` (`rootInstance.adapter`): `.state`, `.doc`, `.dispatch(tr)`, `.focus`. `typeText` = `dispatch(state.tr.insertText(...))`; Enter works as `new KeyboardEvent('keydown', { key: 'Enter', keyCode: 13, bubbles: true, cancelable: true })` on `.ProseMirror` (keyCode needed). ProseMirror positions are 1-based inside the first paragraph: offset n is pos n+1.
- Mock `ElementInternals.setValidity` records calls but `validationMessage`/`validity` are undefined, so a failed validation shows an empty footer; the harness mirrors the last message into `internals.validationMessage`. `checkValidity` is a constant `true` jest.fn: assert `setValidity` args, e.g. `({ valueMissing: true }, message)`; `({}, '')` is valid. Index 0 of `setValidity.mock.calls` is the first mount validation (before the harness mirror).
- Frames: global `requestAnimationFrame` works (setTimeout 0). `flushFrames(page, n)` awaits n rAFs in order (one await per frame, nested rAF needs two). `setupAnimationFrameMocks` is NOT exported from `@/utils`.
- Focus model: `activeElement` is undefined; define it with `Object.defineProperty(document, 'activeElement', { configurable: true, get })` and delete in `afterEach`. `simulateEditorFocus` spies `adapter.focus` with an implementation that sets `activeElement` and dispatches a bubbling `focusin` on `.ProseMirror` (real `view.focus()` does not throw but dispatches nothing). `FocusEvent` and `KeyboardEvent` exist globally, `PointerEvent` does not (use `MouseEvent('pointerdown', { button })`); `window.dispatchEvent(new Event('pointerup'))` reaches the component's window listeners.
- Host element `@Method` proxies are non-writable and async: `jest.spyOn(popoverEl, 'closePopover')` throws; spy `BdsPopover.prototype.closePopover` / `.togglePopoverFn` / `.setAnchorElement` instead, and `await page.waitForChanges()` after the triggering event before asserting calls.
- Late slotted tools: install a fake `global.MutationObserver` that captures the callback, mount, append the `slot="toolbar"` child, invoke the captured callback (`observe` receives `(el, { childList: true })`).
- `classList` iteration is empty in mock-doc: use `el.className` / `classList.contains`.
- `eslint --fix` strips `as X` after `querySelector<X>()` because the package tsconfig is non-strict.

**Real bug found (T8):** `syncLinkAnchor` guards with `=== undefined`, but Stencil nulls the `linkButton`/`linkPopover` refs when the toolbar unmounts, so runtime `readOnly = true` (or a `toolbar` change dropping `link`) throws `Cannot read properties of null (reading 'setAnchorElement')` from `componentDidRender`. Mounting readonly from the start is fine. Two `it.skip` tests in `bds-text-editor.basics.spec.ts` encode the fix; other specs that toggle `readOnly` at runtime use `toolbar: ''` to avoid it.
