# QA Subagent — Per-Scope Memory Index

- [dev:pack:react / dev:pack:vue pipeline](dev-pack-pipeline-commands.md) — never use a plain `vite` server against a workspace-built `boreal-web-components`; use the dedicated pack pipeline, know it installs a tarball snapshot (re-run to pick up component changes), exact commands and cleanup
- [`<template>` content empty in React/Vue](template-content-empty-in-react-vue.md) — JSX/Vue-template children never populate `.content`; ref+`.innerHTML` fix confirmed both frameworks; React `useEffect`-vs-`onMounted` initial-render race on `bds-table` `slot="cell"` (EOA-16000 Task 3) is now RESOLVED at the component level via a `MutationObserver`+`forceUpdate` self-heal in `applyCellTemplate` — verified deterministic across 5 fresh React reloads, no `useLayoutEffect` needed
- [React/Vue Bds* event-detail typing](react-vue-event-detail-typing.md) — never hand-roll event-detail types; derive from the component's own prop signature (React) or the real generic `RowData` shape (Vue); `vue-tsc` CLI can be clean while the IDE still flags a real error
- [`vue/no-useless-template-attributes` false positive](vue-eslint-no-useless-template-attributes-false-positive.md) — verified false positive on a directive-less passthrough `<template ref slot>`; suppress with a scoped eslint-disable, don't restructure working code
- [Playwright + bds-button conventions](playwright-and-bds-button-conventions.md) — shared-browser tab isolation, `bdsClick` vs `click`, `index.html`/testapp playground scenario-accumulation convention
- [Bash sandbox boundary for kill](kill-sandbox-boundary-for-background-tasks.md) — plain `kill`/`kill -9` from Bash silently fails against processes from earlier tool calls (looks identical to "already gone"); use `TaskStop` for tracked background tasks, `dangerouslyDisableSandbox:true` kill (after tracing the process tree) for genuine OS orphans
- [dev:pack build resets playground dev server](dev-pack-build-resets-playground-dev-server.md) — running `dev:pack:react`/`dev:pack:vue` concurrently with active `pnpm dev:components` Playwright interaction causes spurious rebuild/live-reload cycles that silently reset in-page state mid-test; don't interleave, run sequentially instead. Also reproduces from STALE leftover pack processes from an earlier session — check `ps aux` for them before starting a fresh raw dev server.
- [plain `kill` can take down an unrelated background job](plain-kill-can-take-down-unrelated-background-job.md) — killing a stale PID from an earlier session collaterally SIGTERM'd this session's own manually-`&`-backgrounded dev server; prefer the Bash tool's `run_in_background: true` over manual `&`/`disown` for anything that must survive later unrelated `kill` calls
- [querySelector column-key collisions across playground scenarios](resize-testing-false-positives-scoping-and-timing.md) — `document.querySelector('th[data-col-key="x"]')` silently matches the WRONG scenario's column when a playground has multiple `bds-table`s reusing the same colKey; always scope via `bds-table:has(...)`. Also: a single `page.mouse.move()`+`down()`+`move()` without an intermediate wait can occasionally lose a pointer-drag in Playwright — retry with a short `waitForTimeout` between down and move before concluding a resize/drag interaction is broken.
- [bds-table rows-mode items-per-page hydration race](bds-table-rows-mode-itemspp-hydration-race.md) — a non-default `items-per-page` on a slotted `bds-pagination` is silently ignored (falls back to default 10) when `.rows` is set immediately after markup; only use `items-per-page="10"` in QA scenarios or verify actual page boundaries via DOM (fixed via `getEffectiveItemsPerPage()` as of EOA-16000 Task 10)
- [shift+click text-selection vs. manual drag](shift-click-text-selection-vs-manual-drag.md) — verify a shift+click text-selection preventDefault fix via the actual click→shift+click gesture + `getSelection().toString()`, not a manual mousedown/move/up drag across cell text (that's normal unrelated browser behavior and will select text regardless)
- [Storybook Docs-page double-iframe popover positioning](storybook-docs-page-double-iframe-popover-positioning.md) — floating elements (bds-dropdown/bds-popover) using manual getBoundingClientRect()/style.left-top math can render thousands of px off-page ONLY on the Docs page's double-nested iframe, not the plain Canvas tab; always scope queries to the specific instance id or you'll false-negative against an unrelated element
- [bds-table native drag reorder verification](bds-table-reorder-drag-verification.md) — Playwright mouse-based drag never triggers native HTML5 DnD in headless Chromium; dispatch synthetic DragEvents via page.evaluate instead; also isColumnReorderable() rejects pinnable+reorderable columns as drop targets (not a bug)
- [Stencil JSX boolean aria attr renders as empty string](stencil-jsx-boolean-aria-attr-empty-string.md) — `aria-selected={someBoolean}` renders `aria-selected=""` not `"true"`/`"false"`; found in bds-calendar-grid Task 9 QA
- [`playwright-cli` on PATH may resolve to a stale nvm-node20 install](playwright-cli-stale-nvm-shim.md) — always invoke via `.agents/scripts/with-node.sh playwright-cli ...`, not bare `playwright-cli`, or it errors with a missing playwright-core module
- [CDP `CSS.forcePseudoState` unreliable for bg/box-shadow reads](cdp-force-pseudo-state-unreliable.md) — use real hover/focus()/mousedown for hover/focus-visible/active verification instead, re-read computed style once more if first read looks stale
- [bds-calendar-grid Task 9/10 scenario today-fallback quirk](calendar-grid-today-fallback-scenario-quirk.md) — `buildMonthGrid()`'s isToday fallback compares real system date, so real-today's cell also gets `--today` styling in these scenarios; disambiguate cells by aria-label, not by class
- [WebKit `getComputedStyle().userSelect` reporting quirk](webkit-computed-style-user-select-reporting-quirk.md) — reads as unselectable-broken (`webkitUserSelect: "text"`) even when `user-select:none` genuinely blocks selection; verify with a real mousedown-drag-mouseup + `getSelection()` check, not computed style, in WebKit
- [bds-date-picker calendar-grid width mismatch — RESOLVED](bds-date-picker-calendar-grid-width-mismatch.md) — fixed via negative table margin + recalculated header width; re-verified 2026-08-19; measure first/last `<td>`, not `<table>` rect, when re-checking (border-spacing edge padding)
- [bds-popover data-hidearrow attribute inverted name](bds-popover-data-hidearrow-attribute-inverted-name.md) — attribute is bound to canShowArrow (the inverse); check the actual `.popover-arrow` element, never this attribute's presence, when verifying arrow visibility
- [bds-button `--bds-button-height` clamped by `--bds-button-min-height`](bds-button-height-hook-clamped-by-min-height.md) — overriding `--bds-button-height` below the size variant's floor (24/32/44px) is silently clamped back up by the untouched `--bds-button-min-height`; confirmed in bds-date-picker AND recurring in bds-popover.scss's own baseline close-button styling (20×24px not 20×20px), EOA-16692
- [bds-button hover/focus shadows use fixed-size tokens, don't scale below natural floor](bds-button-hover-focus-shadows-fixed-size-tokens.md) — 16px override on bds-date-picker's popover close button: focus ring swells box ~50% (vs ~12.5% at natural 32px), icon off-center ~2.26px + overflows button edge ~0.5px; nav buttons at natural 32px show none of this, EOA-16692
