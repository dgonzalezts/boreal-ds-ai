# QA Subagent — Per-Scope Memory Index

- [dev:pack:react / dev:pack:vue pipeline](dev-pack-pipeline-commands.md) — never use a plain `vite` server against a workspace-built `boreal-web-components`; use the dedicated pack pipeline, know it installs a tarball snapshot (re-run to pick up component changes), exact commands and cleanup
- [`<template>` content empty in React/Vue](template-content-empty-in-react-vue.md) — JSX/Vue-template children never populate `.content`; ref+`.innerHTML` fix confirmed both frameworks; React `useEffect`-vs-`onMounted` initial-render race on `bds-table` `slot="cell"` (EOA-16000 Task 3) is now RESOLVED at the component level via a `MutationObserver`+`forceUpdate` self-heal in `applyCellTemplate` — verified deterministic across 5 fresh React reloads, no `useLayoutEffect` needed
- [React/Vue Bds* event-detail typing](react-vue-event-detail-typing.md) — never hand-roll event-detail types; derive from the component's own prop signature (React) or the real generic `RowData` shape (Vue); `vue-tsc` CLI can be clean while the IDE still flags a real error
- [`vue/no-useless-template-attributes` false positive](vue-eslint-no-useless-template-attributes-false-positive.md) — verified false positive on a directive-less passthrough `<template ref slot>`; suppress with a scoped eslint-disable, don't restructure working code
- [Playwright + bds-button conventions](playwright-and-bds-button-conventions.md) — shared-browser tab isolation, `bdsClick` vs `click`, `index.html`/testapp playground scenario-accumulation convention
- [Bash sandbox boundary for kill](kill-sandbox-boundary-for-background-tasks.md) — plain `kill`/`kill -9` from Bash silently fails against processes from earlier tool calls (looks identical to "already gone"); use `TaskStop` for tracked background tasks, `dangerouslyDisableSandbox:true` kill (after tracing the process tree) for genuine OS orphans
- [dev:pack build resets playground dev server](dev-pack-build-resets-playground-dev-server.md) — running `dev:pack:react`/`dev:pack:vue` concurrently with active `pnpm dev:components` Playwright interaction causes spurious rebuild/live-reload cycles that silently reset in-page state mid-test; don't interleave, run sequentially instead. Also reproduces from STALE leftover pack processes from an earlier session — check `ps aux` for them before starting a fresh raw dev server.
- [plain `kill` can take down an unrelated background job](plain-kill-can-take-down-unrelated-background-job.md) — killing a stale PID from an earlier session collaterally SIGTERM'd this session's own manually-`&`-backgrounded dev server; prefer the Bash tool's `run_in_background: true` over manual `&`/`disown` for anything that must survive later unrelated `kill` calls
- [querySelector column-key collisions across playground scenarios](resize-testing-false-positives-scoping-and-timing.md) — `document.querySelector('th[data-col-key="x"]')` silently matches the WRONG scenario's column when a playground has multiple `bds-table`s reusing the same colKey; always scope via `bds-table:has(...)`. Also: a single `page.mouse.move()`+`down()`+`move()` without an intermediate wait can occasionally lose a pointer-drag in Playwright — retry with a short `waitForTimeout` between down and move before concluding a resize/drag interaction is broken.
