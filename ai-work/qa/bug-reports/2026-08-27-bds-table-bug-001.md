# BUG: `bds-table` and `bds-calendar-grid` leak unscoped `table`/`th`/`td` CSS onto each other

**Severity:** Medium
**Priority:** P2
**Type:** UI / Styling
**Status:** Fixed
**Component(s):** `bds-table`, `bds-calendar-grid` (used by `bds-date-picker`), `boreal-docs` preview CSS
**Fixed in:**

- `packages/boreal-web-components/src/components/data-visualization/bds-table/bds-table/bds-table.scss` — nested every top-level `table`/`thead`/`th`/`td`/BEM-class selector under a single `bds-table { }` host block
- `packages/boreal-web-components/src/components/forms/bds-date-picker/bds-calendar-grid/bds-calendar-grid.scss` — same nesting fix, under `bds-calendar-grid { }`
- `apps/boreal-docs/.storybook/styles/preview.css` — `:not(.docs-story *)` → `:not(:where(.docs-story *))`; boosted `.docblock-argstable` specificity; removed two dead rules; dropped a redundant `word-wrap` alias

**Introduced by:** Not determined during this session (pre-existing in `bds-table.scss` since the component's original implementation; surfaced now because `bds-calendar-grid` — new on this branch — is the first other component to also render a native `<table>`)

**Jira:** [EOA-17495](https://telesign.atlassian.net/browse/EOA-17495) (documentation subtask, under EOA-17277) · Related feature: EOA-17138

## Description

`bds-table.scss` and `bds-calendar-grid.scss` each shipped **top-level, unscoped** CSS selectors (`table`, `thead`, `th`, `td`, `thead th`, and BEM classes like `.bds-table__wrapper`) sitting *outside* their component's `bds-table { }` / `bds-calendar-grid { }` block. Stencil compiles this SCSS straight into each component's global stylesheet, so these bare selectors applied to **any** matching element on the page — not just the component's own markup — the moment that stylesheet loaded into the document.

Both components' stylesheets can be loaded simultaneously in a single Storybook session (the docs preview iframe persists across SPA navigation between story pages, and in a real consumer app both components can simply appear on the same page). When that happens:

- `bds-table`'s `thead th { padding-inline: ...; height: 44px; text-align: left; }` leaked onto `bds-calendar-grid`'s weekday-header cells, forcing "Sun" to wrap into "S / u / n" across three lines instead of rendering on one line, and misaligning the header row against the day-number grid below it.
- `bds-calendar-grid`'s `table { width: ...; }` / `thead th { width: ...; padding: 0; text-align: center; }` leaked onto `bds-table`'s own header row in the reverse direction, in whichever session order caused that stylesheet to load second.

This is **not Storybook-specific** — it's a genuine defect in the shipped component CSS bundle that would affect any production app rendering both `bds-table` and `bds-date-picker` on the same page, on first render, with no navigation or SPA session involved.

A related, secondary issue was found and fixed in `apps/boreal-docs/.storybook/styles/preview.css`: the docs-content table styling rules were themselves unscoped in a similar way (so they also reached into these two components' canvas-rendered tables specifically inside Storybook), and separately had a CSS specificity bug — a `:not(.docs-story *)` exclusion guard inadvertently *added* specificity (via the class inside `:not()`), causing the base content-table rule to override Storybook's own auto-generated `.docblock-argstable` props table at every viewport width, most visibly at narrow widths where the props table's `Default`/`Control` columns were pushed out of view.

## Steps to Reproduce

**Pre-fix, minimal repro (single SPA hop, no round trip needed):**

1. Run `pnpm dev:docs` from the monorepo root; open Storybook.
2. Navigate to `Data Visualization / Table → Overview` — any story renders a canvas `<bds-table>`, loading its stylesheet.
3. Navigate (client-side, no page reload) to `Forms / Date Picker → Overview`.
4. Click any date-picker trigger to open the calendar popover.
5. Observe the weekday header row.

**Reproduction Rate:** Always (100%, deterministic) — once `bds-table`'s stylesheet has loaded anywhere in the session, every subsequently-rendered `bds-calendar-grid` is affected. A hard page reload of the Date Picker page in isolation (never having loaded `bds-table`'s stylesheet) does not reproduce it, which is what made this look timing-dependent at first — it isn't; it's purely "has the other component's stylesheet loaded yet."

---

## Expected Behavior

Each component's table styling is scoped to its own markup and never affects another component's tables, regardless of load order, navigation history, or which stylesheets have been injected into the page.

`Sun Mon Tue Wed Thu Fri Sat` renders on a single line, correctly aligned above the day-number grid, in every session state.

---

## Actual Behavior

Weekday headers rendered wrapped, one letter per line ("S / u / n", "M / o / n", …), with header cell padding, width, and text-alignment all taken from `bds-table`'s SCSS instead of `bds-calendar-grid`'s own. In the reverse load order, `bds-table`'s own header row could similarly be squeezed/misaligned by `bds-calendar-grid`'s leaked styles.

## Root Cause

### `bds-table.scss` (and mirror-image in `bds-calendar-grid.scss`)

```scss
// BEFORE fix (broken) — top-level, unscoped, outside any component block:
bds-table {
  display: flex;
  /* ...host styles... */
}

table {
  width: 100%;
  table-layout: fixed;
  /* applies to ANY <table> on the page */
}

thead th {
  padding-block: $boreal-spatial-padding-s;
  padding-inline: $boreal-spatial-padding-m $boreal-spatial-padding-xs;
  /* applies to ANY <thead><th> on the page */
}
```

Because `bds-table` (and `bds-calendar-grid`) render with `shadow: false` (light DOM), there's no Shadow DOM boundary to contain these selectors even if they *had* been intentionally scoped by encapsulation — but they weren't scoped at all, being simple bare-tag/bare-attribute selectors compiled straight into the component's global CSS bundle by Stencil.

```scss
// AFTER fix (correct) — nested under the host block, including the BEM class block:
bds-table {
  display: flex;
  /* ...host styles... */

  table {
    width: 100%;
    table-layout: fixed;
  }

  thead th {
    padding-block: $boreal-spatial-padding-s;
    padding-inline: $boreal-spatial-padding-m $boreal-spatial-padding-xs;
  }

  .bds-table {
    &__wrapper { /* ... */ }
    /* ...all BEM classes, now compiled as `bds-table .bds-table__wrapper` etc... */
  }
}
```

SCSS nesting under the host tag makes every previously-bare selector compile to `bds-table <selector>` (a genuine descendant combinator), so it can only ever match inside an actual `<bds-table>` element. The identical pattern was applied to `bds-calendar-grid.scss`.

### `apps/boreal-docs/.storybook/styles/preview.css` (secondary)

```css
/* BEFORE fix — :not() inherits its argument's specificity, silently boosting the guarded rule: */
.sbdocs-content table:not(.docs-story *) {
  /* specificity (0,2,1) — 2 classes (.sbdocs-content + the .docs-story inside :not()) + 1 type */
}
.sbdocs-content .docblock-argstable {
  /* specificity (0,2,0) — 2 classes, 0 types — now LOSES to the rule above on the type-selector tiebreak */
}
```

```css
/* AFTER fix — :where() always contributes zero specificity: */
.sbdocs-content table:not(:where(.docs-story *)) {
  /* specificity restored to (0,1,1), same as before any :not() guard existed */
}
.sbdocs-content.sbdocs-content .docblock-argstable {
  /* specificity boosted to (0,3,0) via the doubled-class trick — same technique Storybook's
     own emotion-injected styles use (.css-XXXXX.css-XXXXX) — reliably wins regardless of
     stylesheet injection order */
  table-layout: fixed; /* also made explicit — was previously falling through to the base
                           rule's table-layout: auto, which let unbreakable content force the
                           table wider than its specified 100% width under auto layout */
}
```

## Fix Applied

1. `bds-table.scss` — merged the two previously-duplicate top-level `bds-table { }` blocks into one, and nested the entire BEM class block (`.bds-table { &__wrapper {...} ... }`) inside it too, so `bds-table` compiles to a single selector occurrence with everything properly scoped.
2. `bds-calendar-grid.scss` — identical nesting fix for `bds-calendar-grid { }`.
3. `preview.css`:
   - `.sbdocs-content table:not(.docs-story *)` → `:not(:where(.docs-story *))` (and the paired `th`/`td` word-wrap rule) — restores original specificity while keeping the canvas-table exclusion functional.
   - `.docblock-argstable` — specificity boosted via doubled class, plus explicit `table-layout: fixed`.
   - Removed `.sbdocs-content .sbdocs-preview table:not(.docs-story *)` — confirmed dead: zero tables on the Table docs page live under `.sbdocs-preview` without also being under `.docs-story`, already excluded by the base rule.
   - Removed `.sbdocs-content .bds-doc__wide-table table` — confirmed dead: its only consumer, `KeyboardDocs.tsx`, no longer applies that class (removed independently during this session), and no other file references it.
   - Dropped the redundant `word-wrap: break-word` line, keeping only `overflow-wrap: break-word` (the modern standardized property; `word-wrap` is a legacy alias of the same property — verified via `getComputedStyle`, both report the same value from setting either one).

**Verified:**

- Compiled CSS diffed before/after for both components (`bds-table.css`, `bds-calendar-grid.css`): 92 → 92 rule blocks, 261 → 261 declarations (`bds-table`); 20 → 20 rule blocks, 62 → 62 declarations (`bds-calendar-grid`) — zero styles lost or duplicated, only selector scoping changed.
- Full `boreal-web-components` unit test suite: **295 suites / 3,209 tests passing** (1 pre-existing unrelated todo).
- `prettier --check` clean on all touched SCSS files.
- Live-verified in Storybook via the exact minimal repro (single SPA hop, no round trip) — calendar renders correctly, `bds-table`'s own canvas rendering unaffected, pinned-columns/sticky-header/sort-icon behavior all intact.
- Cross-checked the `Properties` args table and general content-table rendering, at full width and at 775px, against the last-released Chromatic build (`release-current`) — pixel-for-pixel match on `width`/`max-width`/`table-layout` computed values. The date-picker feature itself predates this branch's Chromatic baseline (`NoStoryMatchError` when navigating to it on `release-current`), so calendar-specific verification was done locally with a controlled before/after comparison instead.
