`examples/react-testapp/node_modules/@telesign/boreal-react` resolves through a pnpm virtual-store path keyed like `@telesign+boreal-react@file+examples+react-testapp+...` — a `file:` protocol dependency, not `workspace:*`. When verifying a `boreal-web-components` fix live in `examples/react-testapp` or `examples/vue-testapp` (e.g. via playwright-cli against the Vite dev server), a full `stencil build` from a deleted `dist/` plus `rm -rf node_modules/.vite` plus a hard page reload was **not** sufficient to make the browser reflect the new code — it kept showing pre-fix behavior even though the freshly-built `packages/boreal-web-components/components-build/bds-table.js` (the actual file resolved by `@telesign/boreal-web-components`'s `./components/*.js` export map entry, which is what `boreal-react`'s `dist/index.js` re-exports from) demonstrably contained the fix string.

**Why:** not fully root-caused, but the working hypothesis is that the `file:`-protocol virtual-store linking (as opposed to a live symlink) doesn't reliably propagate source-directory edits without a `pnpm install` to relink, and/or Vite's dependency graph for these apps caches more than just `node_modules/.vite/deps` in a way a single cache-dir deletion doesn't fully invalidate.

**How to apply:** don't trust a live React/Vue example-app repro as evidence a `boreal-web-components` fix is (or isn't) working unless you've first confirmed with a trivial, unambiguous marker (e.g. grep a unique new string in the freshly built `components-build/*.js` AND independently confirm the browser is actually executing that exact file, e.g. via a deliberately-wrong control value) that the app is serving current code. When in doubt, verify the underlying fix in Storybook (`/boreal-wc` static mount, see [[stencil-dev-server-hashed-chunk-stale-cache]]) first — that path was more reliably fixable via cache-busting during the EOA-16000 resize-fix pass — and treat React/Vue-parity verification as needing its own dedicated, possibly `pnpm install`-driven, setup pass. Don't run a full workspace `pnpm install` unilaterally mid-task in a shared/multi-agent session without flagging it — it's a heavier, less reversible action than a component rebuild.
